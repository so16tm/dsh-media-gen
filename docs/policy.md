# DeepSeek Harness 画像・動画生成プラグイン 実装方針

> **ステータス**：設計方針（未実装・未検証）  
> **更新日**：2026-10-14  
> **仮称**：`dsh-media-gen`  
> **文書版**：1.1（日本語ロケール標準対応を追加）

## 1. 結論

DeepSeek Harness（以下 DSH）の **画像生成・動画生成を統合した Cordis プラグイン**を作る。

最大の設計原則は、**DSH 本体に登録済みのプロバイダー設定・認証情報を再利用すること**。プラグイン側で API キーを二重登録させず、プロバイダーごとに利用可能な画像・動画生成モデルを検出して選択できるようにする。

初期対応は **OpenRouter 経由の画像生成・動画生成**とし、OpenRouter 上の xAI、Google などの対応モデルを利用する。Google・xAI の直接 API 対応は後続段階とする。

**日本語（`ja-JP`）と英語（`en-US`）のロケール対応も初期 MVP の必須要件とする。** 原則として DSH 本体の言語設定と i18n 機構を継承し、独自の言語設定を増やさない。

## 2. 目標と対象範囲

### 必須要件

1. **設定共有**：DSH に登録されたプロバイダー ID、接続先、認証情報の参照を利用する。
2. **モデル選択**：画像生成用・動画生成用のモデル一覧を別々に表示し、機能対応を基準に選べる。
3. **動的モデル検出**：API が返す利用可能モデルと対応パラメーターを取得する。モデル ID をコードに固定しない。
4. **画像生成**：テキストから画像を生成し、成果物として保存・表示する。
5. **動画生成**：テキストから動画を生成し、非同期ジョブの受付・状態確認・取得を扱う。
6. **DSH 連携**：モデルから呼べるツールを提供し、チャットから生成を依頼できる。
7. **運用安全性**：利用料金、認証、出力ファイル、エラー、リトライ、実行上限を適切に扱う。
8. **標準ロケール対応（MVP 必須）**：`ja-JP` と `en-US` の UI・通知・エラー表示に対応し、DSH 本体のロケールを自動継承する。未翻訳の場合は英語へフォールバックする。

### 初期スコープ外

- DSH 本体の LLM プロバイダー管理 UI やモデル選択機能を大幅に改造すること。
- あらゆるプロバイダーの固有 API を最初から網羅すること。
- 複雑な動画編集、タイムライン編集、音声合成ワークフロー。
- 複数モデルへの無断同時送信や、料金が発生する自動フォールバック。

## 3. アーキテクチャ

```text
DSH 本体のプロバイダー設定
  ├─ Provider ID / Base URL / 接続方式
  └─ Credential Reference（DSH の秘密情報ストア）
                 │
                 ▼
        dsh-media-gen (Cordis)
  ├─ ProviderBridge      設定・認証情報の参照
  ├─ CapabilityCatalog   画像/動画モデルと対応機能の検出
  ├─ MediaAdapter        プロバイダー別 API 差分の吸収
  │    └─ OpenRouterAdapter（初期実装）
  ├─ MediaJobStore       動画ジョブの永続化・再開
  ├─ MediaTools          DSH エージェント向けツール
  ├─ MediaOutput         画像/動画の保存・表示
  └─ MediaLocale         DSH ロケール連携・日英翻訳・フォールバック
                 │
                 ▼
       DSH チャット / 成果物表示
```

プラグインは Cordis のサービス依存性とライフサイクルに従い、DSH の `tools` サービスへ機能を登録する。**本体の既存プロバイダー設定をプラグインからどう安全に参照できるかは、実装前に実コードで確認する**。公開 API がなければ、内部設定ファイルの直接解析を恒久設計とせず、設定参照ブリッジや小さな共通サービスを検討する。

## 4. プロバイダー設定の共有方針

- **SSOT（単一の設定元）は DSH 本体**。原則としてプラグイン専用の API キー入力欄を設けない。
- プロバイダーの識別子・Base URL・認証情報参照を取得し、リクエスト送信時に認証情報を解決する。
- DSH には認証情報参照と秘密値を分離する `dsh-credentials` がある。秘密値の取得が必要な場合は、公開された資格情報サービスの正規 API を用いる。
- **チャットモデル用の API プロトコル**（例：OpenAI Chat Completions）と、**画像/動画生成用エンドポイント**は別物として扱う。既存のチャット向けアダプターで画像/動画生成まで動くと仮定しない。
- OpenRouter への接続設定が DSH に複数ある場合は、各 `providerId` を区別する。モデル指定は `providerId + modelId` の組で保持する。
- 認証情報が不足する、または当該プロバイダーが生成 API に非対応の場合は、設定画面・ツール応答で理由を明示する。

## 5. モデル検出・選択

### OpenRouter 初期実装

| 用途 | モデル一覧 API | 実行 API |
|---|---|---|
| 画像 | `GET /api/v1/images/models` | `POST /api/v1/images` |
| 動画 | `GET /api/v1/videos/models` | `POST /api/v1/videos` |

- 取得したモデルを **画像**と**動画**で分類する。
- モデル名、ID、対応入力（例：参照画像）、解像度、アスペクト比、長さ、音声生成、料金情報（取得できる範囲）を正規化する。
- API から返される機能情報を元に選択 UI の項目を制御し、非対応パラメーターは送信しない。
- 一覧の再取得ボタンと期限付きキャッシュを設ける。取得失敗時は前回情報を「古い可能性あり」と表示し、無条件に生成可能とは扱わない。
- DSH の**会話モデル一覧**に当該モデルが載っていることを必須条件にしない。生成専用カタログから選ぶ。
- デフォルトの画像モデルと動画モデルを個別に設定できるようにする。存在しない・利用できないデフォルトは選び直してもらう。

モデル例：OpenRouter 経由の Google Gemini 画像生成、xAI Grok Imagine 動画生成、Google Veo 動画生成など。**具体的なモデル ID・提供状況・料金は取得時点の API 応答に従う**。

## 6. 生成処理

### 画像生成

1. プロンプト、プロバイダー、モデル、対応パラメーターを受け取る。
2. 認証情報とモデル能力を検証して `POST /api/v1/images` を呼ぶ。
3. 結果の画像データ（例：Base64）を検証・デコードして成果物として保存する。
4. チャットにプレビュー、ファイルへの参照、生成条件、取得できた実料金を返す。
5. 参照画像を使った編集・バリエーション生成は、対応モデルを判別したうえで追加する。

### 動画生成

1. プロンプト、モデル、尺、解像度などを検証し `POST /api/v1/videos` でジョブ登録する。
2. 返却されたジョブ ID、プロバイダー ID、作成日時、リクエスト条件を永続化する。
3. `GET /api/v1/videos/{jobId}` で `pending` / `in_progress` / `completed` / `failed` を追跡する。
4. 完了後、`GET /api/v1/videos/{jobId}/content` 等で成果物を取得・保存する。
5. チャットに状態・エラー・再取得方法を表示する。

動画は **非同期ジョブ前提**とし、画面を閉じた場合や DSH の再起動後にも未完了ジョブを追跡できる設計を目指す。ポーリング間隔、打ち切り条件、ジョブ保存先、Webhooks の採用可否は実装時に決める。プロバイダー側に取消 API がない場合、ローカル監視の停止を「生成キャンセル」と誤表示しない。

## 7. DSH への公開インターフェース

最低限、以下のエージェントツールを公開する（**名前は仮**）。

| ツール | 用途 |
|---|---|
| `media_list_models` | 設定済みプロバイダーの画像・動画対応モデルと機能を確認 |
| `media_generate_image` | 画像生成を実行 |
| `media_generate_video` | 動画生成ジョブを登録 |
| `media_get_job` | 動画ジョブの状態と結果を取得 |

UI は、プロバイダー選択、モデル選択、モデルに応じたパラメーター表示、画像プレビュー、動画プレイヤー、成果物保存への導線を想定する。**これらの表示文言は MVP から日本語・英語に対応する。** ただし **DSH 標準の添付ファイル・メディア描画機構に連携できるか要調査**。可能なら標準機能を優先し、独立したギャラリー UI は後回しにする。

## 8. 日本語・英語ロケール標準対応（MVP 必須）

### 基本方針

- **標準対応言語**：日本語 `ja-JP` と英語 `en-US` を初期リリースから提供する。日本語は正式サポート対象とし、開発後の追加翻訳扱いにしない。
- **DSH の言語設定を継承**：DSH 本体が公開する locale / i18n サービスを優先し、プラグイン独自の言語切替設定は原則設けない。ユーザーが DSH の言語を切り替えた場合、プラグイン表示も追従する。
- **ロケール正規化**：DSH 側の値が `ja` / `en` などの場合は、それぞれ `ja-JP` / `en-US` に対応付ける。判定できないロケールや未翻訳キーは `en-US` へフォールバックする。
- **辞書による翻訳**：UI 文言をハードコードせず、言語別の i18n 辞書で管理する。ファイル名・配置は DSH/Cordis の既存規約に合わせる（例：`locales/ja-JP.json`、`locales/en-US.json`）。
- **値と表示の分離**：モデル ID、API パラメーター、ツール名、エラーコードは言語によらず安定させ、ユーザー向け説明・ラベルのみ翻訳する。モデル固有の正式名称は原則そのまま表示する。

### 翻訳対象

| 対象 | 必須範囲 |
|---|---|
| 設定画面 | プロバイダー・モデル選択、生成条件、保存先、上限・料金表示 |
| 生成 UI | 画像/動画タブ、開始・更新・再試行、確認ダイアログ、空状態、ファイル操作 |
| ジョブ状態 | 待機中・処理中・完了・失敗などの状態と進捗・再取得の案内 |
| エラー・通知 | 認証エラー、残高・料金、レート制限、非対応モデル、タイムアウト、生成失敗 |
| ツールのユーザー向け文言 | ツール説明・結果メッセージなど、DSH のツール表示機構でローカライズ可能な部分 |
| 表示形式 | 日付・時刻・数値・通貨などはロケールに応じて書式化。金額の通貨単位・数値自体は改変しない |

外部 API が返す自由文のエラーは翻訳済みの共通エラー分類に対応付ける。元のメッセージを表示する場合も秘密情報を除去し、未翻訳であることが分かる形にする。ユーザーが入力したプロンプトの**自動翻訳は行わない**（明示的な指示がある場合を除く）。

### 受け入れ条件と確認事項

1. DSH を `ja-JP`（または `ja`）に設定すると、プラグインの主要 UI、生成状況、エラーが日本語になる。
2. DSH を `en-US`（または `en`）に設定すると、同じ画面・処理が英語になる。
3. ロケール変更に追従し、プラグイン専用の言語設定や API キー入力を要求しない。
4. 未翻訳キーや未対応言語でも画面が壊れず、英語の文言にフォールバックする。
5. 画像・動画の生成成功、認証失敗、レート制限、ジョブ失敗、料金の確認などの主要経路で日英の表示テストを実施する。

**要検証**：DSH 本体の locale / i18n 取得・変更通知・辞書登録 API は実コードで確認する。機構が存在しない場合の互換レイヤーは検討するが、「本体のロケールに追従する」という要件は維持する。

## 9. コスト・安全性・信頼性

- **課金**：送信前にモデルの料金または概算可能な費用を表示する。価格が取得できなければ「不明」と示す。実行後は API から返る `usage.cost` 等を記録する。概算を確定料金と扱わない。
- **承認**：高額・連続生成を想定し、1回あたりの件数や並列数に上限を設ける。課金が発生する自動リトライ・モデル切替は慎重に制御する。
- **秘密情報**：API キーを設定ファイル、ジョブ DB、エラーログ、ツール戻り値、成果物メタデータに保存しない。
- **入力検証**：サイズ・MIME・長さ・参照画像の扱いを制限し、任意 URL の取得を許す場合は SSRF 対策を行う。
- **ファイル管理**：成果物サイズ、保存先、アクセス制御、保持期間、削除手段を定義する。外部の一時 URL だけに依存しない。
- **障害対応**：401/402/429/5xx、タイムアウト、ジョブ失敗を区別する。冪等性や重複課金が未保証の POST を無条件に再実行しない。
- **互換性**：API の提供状況・対応パラメーター・DSH 内部構造の変更に備え、アダプターとモデル能力判定を分離する。

## 10. 実装ステップ

| 段階 | 内容 | 完了条件 |
|---|---|---|
| **0. 接続調査** | DSH のプロバイダー設定取得、`dsh-credentials`、ツール登録、保存・描画 API、**locale / i18n 機構**を実コードで確認 | API キーを再登録せず OpenRouter に接続でき、DSH ロケール取得方法を特定できる |
| **1. 画像 MVP** | OpenRouter モデル検出、画像生成、保存、チャット出力、**日英辞書とロケール継承の実装** | 対応モデルで画像を生成・表示でき、主要 UI・成功/失敗表示が日英で動作する |
| **2. 動画 MVP** | 動画モデル検出、ジョブ投入・永続化・ポーリング、保存、再開、**動画ジョブの日本語・英語表示** | 動画を取得でき、再起動後のジョブ追跡と日英の状態・エラー表示が動作する |
| **3. 操作性・堅牢化** | 条件付き UI、参照画像、料金表示、上限、エラー処理、**翻訳漏れの検出と日英回帰テスト** | 非対応機能や認証・料金エラーを適切に扱え、ロケール切替・フォールバックを検証済み |
| **4. 拡張** | Google / xAI 直接 API、追加プロバイダー、ギャラリー高度化 | アダプター追加だけで対応範囲を広げられる |

## 11. 実装前に確認する項目

- [ ] DSH に登録されたプロバイダー一覧・設定・資格情報参照を取得する**正式な API**の有無。
- [ ] **DSH 標準ロケール/i18n API** の有無、対応ロケール表記、切替通知、翻訳辞書の登録方法。
- [ ] 設定画面・ツール表示・ジョブ通知での日英ローカライズ範囲と、未翻訳時のフォールバック挙動。
- [ ] OpenRouter を DSH に追加した際の設定表現、Base URL と生成 API パスの組み立て方。
- [ ] モデル一覧取得時の権限・アカウント固有の利用可否をどこまで判定できるか。
- [ ] DSH のツール返却値が画像・動画ファイルをどう表現し、Web UI がどう描画するか。
- [ ] ジョブ永続化、再起動時の回復、保存場所、ファイルアクセス権の既存基盤。
- [ ] 画像・動画 API のパラメーター、利用料金、提供モデルの最新仕様。
- [ ] DSH の対象バージョンと、変更の多い公開 API への互換性方針。
